# 数据与方法

## 1. 输入和质量

使用原发布方 `events.csv`，SHA-256：`3745aa83238b1e6d44d8fda209807899f420084398f94ddf745f3cbcfecbf9e7`。全部 2,756,101 行进入质量检查；非法时间、负编号、未知事件类型和购买缺订单号共 0 行；完全重复记录 460 行，清洗后 2,755,641 行。非购买事件缺少订单号是正常现象。

| 字段 | 含义 | 处理 |
|---|---|---|
| timestamp | Unix 毫秒时间戳 | 统一 UTC，保留毫秒用于严格先后判断 |
| visitorid | 匿名访客编号 | 不能据此确定自然人身份或注册时间 |
| event | view / addtocart / transaction | 分别为浏览、加购、购买事件 |
| itemid | 匿名商品编号 | 全流程保留原编号，不推断品类/价格 |
| transactionid | 订单编号 | 购买应有效；非购买允许为空 |

去重键为五个原始字段组合。不同时间对同一商品的重复浏览保留。用户维表一人一行，关联前后行数、不匹配记录和主键唯一性均检查。CSV原始顺序仅用于同毫秒时稳定排序，不当作严格时间先后证据。

## 2. 会话和购物路径

同一访客相邻事件间隔 **超过30分钟** 开启新会话，恰好30分钟仍属于原会话。第一条记录也开启会话。浏览、加购和购买都参与会话切分。

漏斗单位为“访客-会话-商品配对”：每个配对最多计一次。浏览后加购、浏览后购买均要求时间严格晚于首次浏览；严格三步还要求购买严格晚于首次有效加购。同毫秒事件不认定为先后行为。

- 分母：有浏览的商品-访问配对 2,330,774。
- 浏览后加购：45,114 / 2,330,774 = 1.936%。
- 浏览后购买：17,237 / 2,330,774 = 0.740%。
- 严格三步：14,807 / 2,330,774 = 0.635%。

两种购买口径不是互斥分组。三步漏斗不覆盖未记录加购、跨会话购买等路径。日趋势是事件次数；分层转化以“有浏览的会话”为分母、出现至少一条有效浏览后购买路径的会话为分子。首次观测访问不等于新注册用户；历史访问差异是观察关联，不能解释为回访造成购买。

## 3. 固定时间切分的推荐评估

训练：2015-08-01 UTC之前；验证：8月；测试：9月1日至数据结束。模型在验证前冻结，既不按验证调参，也不使用验证或测试行为更新共现与热门度。验证标签必须在9月1日前；跨边界会话不借用测试期标签。

每个留出会话首次浏览时预测下一次**严格更晚、不同商品**的浏览。一个会话最多一个预测点。同毫秒浏览不当作下一次浏览；没有可用后续标签的点单独报告，不能把带标签子样本覆盖面扩大到全部访客。

测试期200,912个预测点中28,166个有标签；172,746个在观测窗口内无合规后续浏览。3,166个标签商品未出现在训练商品目录，仍保留在两种方法的分母并计未命中。

**热门基线：**训练期商品浏览次数排序，推荐10件，排除当前商品。

**共同浏览：**训练会话内不同商品共现；每会话最多取最早50件不同商品，避免超长会话导致成对展开过大；至少2次会话支持，使用 `共现次数 / sqrt(商品A会话数 × 商品B会话数)` 排序，取最多10件。不足时按热门补齐、去重并排除当前商品。两方法候选商品均固定在训练期199,510件商品目录。

- HR@10：预测列表命中下一不同商品的预测点数 / 有标签预测点数。
- 覆盖率：实际推荐过的不同商品数 / 训练商品目录规模。
- 完全回退热门：共同浏览列表没有任何关联候选的预测点比例；部分补足不计完全回退。
- 不确定性：以访客为聚类单位，按稳定访客顺序进行600次自助重采样，种子20261108。重复访客的会话一起抽取；配对差异使用同一访客、同一预测点，报告百分位95%区间。

这是一项历史日志上的下一商品预测评估，未有随机曝光和可归因订单；受日志缺失、选择性标签及商品时效性限制。热门基线刻意保持简单，结果不等同于战胜生产推荐系统。

## 4. 独立模拟实验

模拟用户100,000名，1:1随机分组，固定种子20261108。生成概率：对照购买2.5%、处理2.65%；客服接触率0.5%与0.53%。这些是演示假设，与Retailrocket及TikTok实际指标无关。

差异区间按独立二项样本正态近似计算；分流检验为自由度1的卡方检验（等价双侧正态形式）。样本量使用双侧α=0.05、80%检验功效、绝对差0.15个百分点的两比例规划公式，见实验设计PDF。模拟样本不足规划量，不靠更换种子寻找显著结果。

## 5. 可审计文件

`reports/metrics.json`保存全部主结果，`reports/validation.json`保存13项全量数据不变量，`tests/`覆盖清洗、严格时序、边界、候选集、未见标签、冻结训练与重采样可复现性。SQL全部保留，原始数据完整保存在Release下载包。
